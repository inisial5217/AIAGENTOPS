## 1. Ringkasan Eksekutif

Fase 2 bertujuan membangun kerangka backend Go (Modular Monolith Domain-Driven Design) yang kokoh, tangguh untuk kebutuhan enterprise, dan terintegrasi secara langsung dengan dependensi nyata tanpa mock data:
- **Server HTTP**: Echo v4 dengan middleware pipeline enterprise (logging terstruktur, recovery panic, CORS ketat, sliding window rate limiter, dan otentikasi stub).
- **Data Persistence & Cache**: Connection pool PostgreSQL 16 (`pgxpool`) dan client Redis 7 (`go-redis/v9`) dengan konfigurasi connection pool teruji dan verifikasi startup liveness.
- **Engine Migrasi Database**: Migrator transaksional native Go yang mengeksekusi dan mencatat 6 pasang skema migrasi DDL pada tabel `schema_migrations`.
- **Standar Observabilitas & Telemetri**: Liveness probe (`/healthz`), Readiness probe (`/readyz`) dengan pemeriksaan multi-komponen live, serta Prometheus metrics (`/metrics`) standar industri.
- **Standar Error RFC 7807**: Struktur `AppError` berbasis Problem Details for HTTP APIs dengan error wrapping dan error singletons.
- **Kepatuhan Agent Instructions**: Seluruh komentar kode mematuhi aturan 1-4 kata bahasa Inggris, ketiadaan banner dekoratif, batas panjang file di bawah 300 baris, penanganan error transparan tanpa panic/os.Exit liar, serta isolasi graceful shutdown 30 detik.

## 3. Rincian Teknis Implementasi Tugas 2.1 - 2.10

### Tugas 2.1: Konfigurasi Aplikasi (`internal/config/config.go`)
- Struct `Config` memuat: `Port`, `Environment`, `LogLevel`, `DatabaseDSN`, `RedisAddr`, `RedisPass`, `DockerHost`, `ArgoCDURL`, `ArgoCDToken`, `TelegramBotToken`, `TelegramChatID`, `AIServiceURL`, `AllowedOrigins`.
- Validasi wajib: Memeriksa keberadaan nilai environment `DATABASE_DSN` dan `REDIS_ADDR`. Jika salah satu kosong, fungsi `config.Load()` segera mengembalikan `fmt.Errorf` deskriptif.

### Tugas 2.2: Structured Logger (`pkg/logger/logger.go`)
- Menggunakan `log/slog` bawaan Go dengan `slog.NewJSONHandler` yang menulis langsung ke `os.Stdout`.
- Service tagging default: `service="cifo-backend"`.
- Konteks terdistribusi: Injeksi `trace_id` dan `span_id` melalui `WithContext(ctx)` dan `ContextWithTrace(...)`.

### Tugas 2.3: Error Handling Standar RFC 7807 (`pkg/apperror/error.go`)
- Format payload JSON:
  ```json
  {
    "type": "about:blank",
    "title": "Bad Request",
    "status": 400,
    "detail": "Detailed reason",
    "code": "BAD_REQUEST",
    "instance": "/api/v1/resource"
  }
  ```
- Error singletons yang disediakan:
  - `ErrUnauthorized` (401, `UNAUTHORIZED`)
  - `ErrForbidden` (403, `FORBIDDEN`)
  - `ErrNotFound` (404, `NOT_FOUND`)
  - `ErrInternal` (500, `INTERNAL_ERROR`)
  - `ErrBadRequest` (400, `BAD_REQUEST`)
  - `ErrRateLimit` (429, `RATE_LIMITED`)
- Mendukung pemenuhan interface `error` standar dengan method `Unwrap() error` untuk error chaining transparan.

### Tugas 2.4: Database Pool & Redis Client (`internal/repository/`)
- **PostgreSQL (`db.go`)**:
  - Pool engine: `github.com/jackc/pgx/v5/pgxpool`.
  - `MinConns`: 5 koneksi minimum selalu standby.
  - `MaxConns`: 25 koneksi batas beban konkuren.
  - `MaxConnLifetime`: 1 jam untuk pencegahan koneksi basi.
  - `MaxConnIdleTime`: 15 menit.
  - `HealthCheckPeriod`: 30 detik.
  - Ping liveness check saat startup dengan timeout 5 detik.
- **Redis (`redis.go`)**:
  - Client engine: `github.com/redis/go-redis/v9`.
  - Startup liveness verification via perintah `client.Ping(ctx)`.

### Tugas 2.5: Migrasi Database Transaksional (`internal/repository/migrator.go` & `migrations/`)
- Runner migrasi otomatis membaca file `.up.sql` dan `.down.sql` berurutan alfabetis/numerik.
- Membuat tabel pelacak `schema_migrations (version VARCHAR PRIMARY KEY, applied_at TIMESTAMPTZ)`.
- Seluruh DDL migrasi dieksekusi di dalam blok transaksi PostgreSQL `pgx.BeginTx`:
  1. `001_create_users`: Tabel `users` dengan UUID v4, email unik, peran RBAC, dan integrasi Keycloak ID.
  2. `002_create_ai_sessions`: Tabel percakapan AI `ai_sessions` dan pesan riwayat `ai_messages` dengan relasi cascade.
  3. `003_create_audit_log`: Tabel kepatuhan audit keamanan `audit_log` dan audit aksi otomatis AI `ai_action_audit_log`.
  4. `004_create_incidents`: Tabel manajemen insiden `incidents` dengan pencatatan status, tingkat keparahan, ringkasan RCA, serta relasi penanggung jawab.
  5. `005_create_ai_usage_tracking`: Tabel pemantauan konsumsi token prompt, token output, dan kalkulasi biaya USD model LLM.
  6. `006_create_notification_settings`: Tabel preferensi pengiriman alert Telegram dan in-app.

### Tugas 2.6: Middleware Pipeline (`internal/middleware/`)
- **Request Logger (`logger.go`)**: Menghitung latensi request dalam milidetik, mencatat status HTTP, IP pengirim, User-Agent, dan Trace ID.
- **Panic Recovery (`recovery.go`)**: Menangkap runtime panic Go menggunakan `recover()`, mencetak stack trace lengkap ke log error, dan membalas client dengan RFC 7807 Problem Details HTTP 500 `INTERNAL_ERROR`.
- **CORS Handler (`cors.go`)**: Mendukung konfigurasi whitelist origin, metode HTTP (`GET, POST, PUT, PATCH, DELETE, OPTIONS`), header standar (`Authorization, Content-Type, X-Request-ID, X-Idempotency-Key`), serta cache preflight `max-age: 3600`.
- **Rate Limiter (`ratelimit.go`)**: Algoritma sliding window log menggunakan Redis Sorted Set:
  - Membersihkan record di luar window: `ZREMRANGEBYSCORE key 0 (now - window)`.
  - Menghitung frekuensi dalam window: `ZCARD key`.
  - Jika `count >= limit`, kembalikan HTTP 429 Too Many Requests (`RATE_LIMITED`).
  - Menambahkan timestamp transaksi: `ZADD key now now`.
  - Memperbarui TTL: `EXPIRE key (window * 2)`.
  - Menghasilkan header standar: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`.
- **Auth Stub (`auth.go`)**: Ekstraksi token Bearer awal untuk menyiapkan context request sebelum integrasi Keycloak Fase 3.

### Tugas 2.7: Health Check Probes (`internal/handler/health_handler.go`)
- **`GET /healthz` (Liveness)**: Menandakan proses Go aktif menerima koneksi (HTTP 200).
- **`GET /readyz` (Readiness)**: Menguji kesiapan 3 komponen esensial secara konkuren:
  - Database: `pool.Ping(ctx)`
  - Redis: `client.Ping(ctx)`
  - Docker daemon: Melalui HTTP API `http://127.0.0.1:2375/_ping` atau named pipe `\\.\pipe\docker_engine`.

### Tugas 2.8: Server Entrypoint & Graceful Shutdown (`cmd/server/main.go`)
- Memuat konfigurasi, menginisialisasi logger, membuka connection pool DB dan Redis.
- Menjalankan auto-migrasi database saat booting server.
- Mengonfigurasi router Echo, mendaftarkan middleware pipeline, dan binding endpoint.
- Graceful shutdown: Menggunakan `signal.NotifyContext` untuk menangkap sinyal interupsi sistem (`SIGINT`, `SIGTERM`). Memberi batas waktu 30 detik untuk menyelesaikan request yang sedang berjalan sebelum menutup koneksi database dan Redis secara bersih.

### Tugas 2.9: Prometheus Metrics Endpoint (`internal/handler/metrics_handler.go`)
- Mengintegrasikan library resmi `github.com/prometheus/client_golang/prometheus/promhttp`.
- Menyediakan metrik aplikasi kustom:
  - `http_requests_total` (Counter berlabel method, path, status_code).
  - `http_request_duration_seconds` (Histogram latensi respons).
  - `active_websocket_connections` (Gauge pemantauan koneksi real-time).
  - `db_pool_active_connections` & `db_pool_idle_connections` (Gauge pemantauan kapasitas connection pool pgx).

### Tugas 2.10: Containerization Dockerfile (`apps/backend/Dockerfile`)
- Multi-stage build berbasis Alpine:
  - Builder stage: static binary compiler (`CGO_ENABLED=0`, `-ldflags="-w -s"`).
  - Runtime stage: `alpine:3.20` dengan pengguna non-root berhak akses terbatas (`appuser`).
  - Container health check: Perintah periodik `wget http://localhost:8080/healthz`.
