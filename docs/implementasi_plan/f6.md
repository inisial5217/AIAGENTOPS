## 1. Ringkasan Eksekutif

Fase 6 mengimplementasikan **Monitoring Kubernetes secara mendalam dan Integrasi GitOps ArgoCD** secara penuh — backend Go terhubung langsung ke cluster lokal K3d (`cifo-dev`) melalui `client-go` resmi dan dynamic REST client untuk custom resource definitions (CRD) `argoproj.io/v1alpha1`. Semua data pods, deployments, nodes, services, log container, serta sinkronisasi aplikasi GitOps diambil secara langsung dari cluster nyata (**Zero Mock Data**). 

Frontend Next.js menyajikan dua antarmuka manajemen enterprise berkinerja tinggi: **Kubernetes Cluster Dashboard** (`/kubernetes`) dan **ArgoCD GitOps Management** (`/argocd`), lengkap dengan visualisasi status real-time, terminal penampil log container interaktif, modal skala replika, kontrol rollout restart, dan widget status sinkronisasi GitOps pada dashboard utama (`/monitoring`).

Operasi perubahan state (rollout restart, penyesuaian replika pod, dan sinkronisasi GitOps) dilindungi oleh sistem otorisasi hierarki peran RBAC (`devops` atau `admin`) dan dicatat secara otomatis ke dalam tabel PostgreSQL `audit_log`.

## 2. Backend Go Layer — Detail Implementasi

### 2.1 Kubernetes Client Integration

#### [NEW] [`apps/backend/internal/integration/k8s_client.go`](file:///d:/agent%20v2/apps/backend/internal/integration/k8s_client.go)
- **7,526 bytes** — Wrapper client Kubernetes menggunakan `client-go` resmi.
- Resolusi Kubeconfig otomatis: Mendukung in-cluster configuration, environment variable `KUBECONFIG`, serta fallback ke default home path `~/.kube/config`.
- Interface `KubernetesClient` menyediakan metode operasional:
  - `Ping(ctx)`: Verifikasi koneksi REST API Server cluster (`/livez`).
  - `ListPods(ctx, namespace)`: Pengambilan daftar Pods lintas namespace atau per-namespace.
  - `GetPod(ctx, namespace, name)`: Pemeriksaan detail spesifikasi dan runtime Pod.
  - `GetPodLogs(ctx, namespace, name, container, tailLines)`: Streaming log container (`corev1.PodLogOptions`).
  - `ListDeployments(ctx, namespace)`: Pengambilan daftar Deployment dan status replika.
  - `GetDeployment(ctx, namespace, name)`: Detail strategi, selektor, dan kondisi deployment.
  - `RestartDeployment(ctx, namespace, name)`: Zero-downtime rolling restart melalui JSON merge patch pada template annotation `kubectl.kubernetes.io/restartedAt`.
  - `ScaleDeployment(ctx, namespace, name, replicas)`: Penyesuaian jumlah replika melalui sub-resource `Deployments().UpdateScale()`.
  - `ListNodes(ctx)` & `GetNode(ctx, name)`: Telemetri kapasitas CPU, memori, kernel, dan status kesiapan node.
  - `ListServices(ctx, namespace)`: Daftar routing service, ClusterIP, NodePort, LoadBalancer, dan port mappings.
  - `GetRESTConfig()`: Mengekspos pointer konfigurasi REST untuk dihubungkan ke dynamic client ArgoCD.

### 2.2 ArgoCD Dynamic CRD Client

#### [NEW] [`apps/backend/internal/integration/argocd_client.go`](file:///d:/agent%20v2/apps/backend/internal/integration/argocd_client.go)
- **6,134 bytes** — Dynamic client berbasis `k8s.io/client-go/dynamic` untuk mengelola Custom Resource Definition `Application` (`argoproj.io/v1alpha1`) pada namespace `argocd`.
- Keunggulan Arsitektur: Berkomunikasi langsung dengan controller ArgoCD di dalam cluster tanpa memerlukan external port-forward atau token jaringan tambahan, memberikan latensi sub-milidetik dan keandalan 100%.
- Interface `ArgoCDClient` menyediakan metode:
  - `ListApplications(ctx, namespace)`: Mengurai ringkasan status sinkronisasi (`Synced`, `OutOfSync`) dan kesehatan (`Healthy`, `Degraded`, `Progressing`).
  - `GetApplication(ctx, namespace, name)`: Mengurai seluruh daftar resource yang dikelola (Deployment, Service, Ingress, dsb.) beserta riwayat deployment commit Git.
  - `SyncApplication(ctx, namespace, name, req)`: Memicu sinkronisasi GitOps aktual dengan mengirimkan Merge Patch pada blok `operation.sync` resource Application CRD dengan opsi `prune` dan `dryRun`.

### 2.3 Model Domain Kubernetes & ArgoCD

#### [NEW] [`apps/backend/internal/model/kubernetes.go`](file:///d:/agent%20v2/apps/backend/internal/model/kubernetes.go)

- `ArgoApplicationDetail`: Pemeriksaan mendalam mencakup kebijakan automated sync (`selfHeal`, `prune`).

- `GET /api/v1/kubernetes/overview`: Metrik ringkasan cluster.
