## 1. Ringkasan Eksekutif

Fase 7 mengimplementasikan **infrastruktur komunikasi real-time dua arah (Bi-directional WebSocket)** secara menyeluruh dari backend Go hingga frontend Next.js 16. Seluruh kebutuhan streaming log kontainer Docker langsung dari Docker Daemon (`Follow: true`), pemantauan cluster events Kubernetes (`WatchEvents` dari `client-go`), multiplexing system event logs, serta in-app notification toasts berbasis tingkat keparahan (severity) telah terpasang dan beroperasi secara penuh tanpa data tiruan (**Zero Mock Data**).

Arsitektur WebSocket backend dirancang dengan standar keandalan tinggi enterprise:
- **Zero Goroutine Leak**: Setiap koneksi client diawasi oleh dua goroutine terisolasi (`readPump` dan `writePump`), pembersihan otomatis hook unregister, dan penutupan stream hulu (upstream) saat tidak ada lagi subscriber aktif (`onTopicEmpty`).
- **Heartbeat & Liveness**: Ping/Pong periodik (ping 30 detik, pong deadline 60 detik) untuk mendeteksi silent network drop atau broken socket.
- **Backpressure & Slow Consumer Protection**: Channel pengiriman berukuran 1000 pesan dengan kebijakan non-blocking drop bila client mengalami lag jaringan, mencegah memory bloating.
- **Autentikasi JWT Query Param**: Mengatasi batasan browser WebSocket standard API yang tidak mendukung custom headers dengan memvalidasi JWT token pada handshake query parameter sebelum upgrade protokol.

Frontend Next.js menyajikan komponen antarmuka real-time berperforma tinggi:
- **WebSocket Client Singleton** dengan algoritma *Exponential Backoff Reconnect* (1s, 2s, 4s, 8s, max 30s) dan otomatisasi pendaftaran ulang langganan topic saat reconnect.
- **Cyberpunk Dark Log Terminal** (`LogTerminal`) dengan syntax highlighting dinamis (Red Error, Amber Warn, Green Info, Cyan Debug), auto-scroll toggle, search filter dengan hitungan pencocokan (match counter), buffer clear, dan fitur export file log lokal.
- **Notification Toast Provider** dengan aturan persistensi waktu tayang cerdas: `CRITICAL` bersifat persisten hingga ditutup user, `WARNING` auto-dismiss 10 detik, dan `INFO` auto-dismiss 5 detik, serta optimalisasi `pointer-events-none` pada container viewport agar tidak menghalangi interaksi tombol UI di bawahnya.
- **Live WS Event Logs** menggantikan polling REST API lama di dashboard utama (`/monitoring`) dengan badge status live dan graceful fallback.

### 2.1 WebSocket Protocol & Data Contracts

#### [NEW] [`apps/backend/internal/ws/message.go`](file:///d:/agent%20v2/apps/backend/internal/ws/message.go)
Mendefinisikan tipe payload dan format pesan WebSocket terstruktur:
- **Tipe Pesan Server (`MessageType`)**:
  - `MessageTypeLogEntry` (`"log_entry"`): Baris log kontainer atau pod stream.
  - `MessageTypeNotification` (`"notification"`): Alert atau pemberitahuan in-app.
  - `MessageTypeMetricUpdate` (`"metric_update"`): Telemetri metrik sistem.
  - `MessageTypeContainerEvent` (`"container_event"`): Event lifecycle kontainer Docker.
  - `MessageTypePodEvent` (`"pod_event"`): Perubahan status Pod Kubernetes.
  - `MessageTypeArgoCDEvent` (`"argocd_event"`): Sinkronisasi/status GitOps ArgoCD.
  - `MessageTypeSystemEvent` (`"system_event"`): Event gabungan sistem untuk monitoring widget.
  - `MessageTypeAck` (`"ack"`): Konfirmasi subscribe/unsubscribe.
  - `MessageTypeError` (`"error"`): Pesan kesalahan server.
- **Aksi Klien (`ClientAction`)**:
  - `ActionSubscribe` (`"subscribe"`): Mendaftar ke topic tertentu.
  - `ActionUnsubscribe` (`"unsubscribe"`): Berhenti berlangganan topic.
  - `ActionPing` (`"ping"`): Deteksi liveness dari klien.
- **Topik Standar**:
  - `TopicNotifications` (`"notifications"`): Siaran pemberitahuan seluruh sistem.
  - `TopicSystemEvents` (`"system_events"`): Agregasi event Docker & Kubernetes.
  - `TopicK8sEvents` (`"k8s_events"`): Watch event khusus Kubernetes.
  - `docker_logs:<container_id>`: Aliran log kontainer spesifik.
- **Structs Kontrak**:
  - `WSMessage`: Wrapper standar `{ type, topic, payload, timestamp }`.
  - `ClientMessage`: Format pesan masuk `{ action, topic, payload }`.
  - `LogPayload`: `{ source, id, stream, log, level }`.
  - `NotificationPayload`: `{ id, title, message, severity, timestamp, link, metadata }`.
  - `EventPayload`: `{ source, event_type, resource, action, message, timestamp }`.

### 2.2 Client Connection & Goroutine Lifecycle

#### [NEW] [`apps/backend/internal/ws/client.go`](file:///d:/agent%20v2/apps/backend/internal/ws/client.go)
Mengelola per-connection socket state dengan kepatuhan tinggi terhadap konkurensi Go:
- **Kapasitas Buffer**: Channel pengiriman berukuran 1000 pesan (`send chan *WSMessage`).
- **Pembersihan Bersih (`Close`)**: Menggunakan `sync.Once` untuk mencegah *panic: close of closed channel* saat unregister dieksekusi bersamaan.
- **Pompa Tulis (`writePump`)**:
  - Mengambil pesan dari channel `send` dan menulisnya ke WebSocket sebagai JSON frame.
  - Mengirim frame WebSocket Ping setiap 30 detik (`pingPeriod = 30 * time.Second`).
  - Mengatur `writeWait = 10 * time.Second` untuk write deadline.
  - Batas ukuran pesan masuk maksimal `maxMessageSize = 65536` byte.
- **Pompa Baca (`readPump`)**:
  - Mengatur `pongWait = 60 * time.Second` dan membaca pesan masuk secara berkelanjutan.
  - Memperbarui read deadline setiap kali menerima frame Pong dari klien.
  - Mengurai pesan JSON `ClientMessage` dan memanggil dispatcher `hub.handleClientMessage`.
  - Menutup soket dan memicu `hub.unregister` saat koneksi terputus atau error.

### 2.3 Central Hub & Topic Registry

#### [NEW] [`apps/backend/internal/ws/hub.go`](file:///d:/agent%20v2/apps/backend/internal/ws/hub.go)
Mengatur seluruh koneksi dan routing pesan berdasarkan publish-subscribe topic:
- **Manajemen Registry**:
  - `clients map[*Client]bool`: Daftar seluruh klien aktif terhubung.
  - `topics map[string]map[*Client]bool`: Pemetaan topic ke himpunan klien subscriber.
  - `clientTopics map[*Client]map[string]bool`: Jejak topic yang dilanggan oleh masing-masing klien untuk proses unregister instan saat disconnect.
- **Topic Empty Hooks (`onTopicEmpty`)**:
  - Fungsi callback yang dipanggil ketika jumlah pelanggan pada suatu topic menjadi 0.
  - Digunakan untuk menghentikan aliran log kontainer Docker hulu (`StreamContainerLogs`) secara instan sehingga tidak membebani Docker daemon saat user menutup modal atau meninggalkan halaman.
- **Metode Thread-Safe**:
  - `Subscribe(client, topic)`: Menambahkan subscriber dan mengirim `MessageTypeAck`.
  - `Unsubscribe(client, topic)`: Menghapus subscriber dan memicu hook pembersihan jika topic kosong.
  - `Broadcast(topic, message)`: Menyebarkan pesan ke seluruh subscriber topic dengan seleksi non-blocking drop jika channel buffer klien penuh.
  - `BroadcastAll(message)`: Menyebarkan pesan penting ke seluruh koneksi aktif.

### 2.4 Live Streaming Engine

#### [NEW] [`apps/backend/internal/ws/streamer.go`](file:///d:/agent%20v2/apps/backend/internal/ws/streamer.go)
Menghubungkan sumber data nyata (Docker Engine & Cluster K3d) ke WebSocket Hub:
- **Docker Log Streamer**:
  - Mendengarkan permintaan subscribe ke format `docker_logs:<container_id>`.
  - Membuka `dockerClient.StreamContainerLogs` dengan opsi `Follow: true` dan `Tail: "100"`.
  - Membaca baris log secara streaming dengan `bufio.Scanner` dan membungkusnya ke `LogPayload`.
  - Mendeteksi level log secara otomatis (`ERROR`, `WARN`, `INFO`, `DEBUG`) berdasarkan ekspresi reguler kata kunci pada baris teks log.
  - Menghentikan goroutine scanner secara bersih melalui pembatalan konteks (`context.CancelFunc`) ketika subscriber terakhir melakukan unsubscribe.
- **Docker Engine Event Watcher**:
  - Menggunakan `dockerClient.ListenEvents` untuk menangkap event runtime kontainer nyata (`start`, `die`, `restart`, `pause`, `destroy`).
  - Mengirimkan event ke topik `TopicSystemEvents` dan `TopicNotifications` secara otomatis (misal: notifikasi `WARNING` jika kontainer berhenti/mati mendadak).
- **Kubernetes Cluster Event Watcher**:
  - Menggunakan `k8sClient.WatchEvents` (`corev1.Event`) untuk memantau siklus hidup pod cluster secara live.
  - Menyaring event tipe `Warning` (seperti `FailedScheduling`, `CrashLoopBackOff`, `OOMKilled`) dan memicu in-app notification bertingkat `WARNING` atau `CRITICAL` ke frontend.
  - Mengirimkan event normal (`Scheduled`, `Started`, `ScalingReplicaSet`) ke topik `TopicSystemEvents`.
