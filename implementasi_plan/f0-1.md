## 5. Rangkuman 5 Solusi Bottleneck & Optimasi Kunci

Selama pengujian live, telah dilakukan 5 perbaikan teknis untuk memastikan aplikasi berjalan **mulus, optimal, maksimal, dan kompatibel**:

1. **Pencegahan Timeout Manifest Besar**:
   - Upstream `install.yaml` ArgoCD sebesar 1.24 MB dipecah menjadi `crds.yaml` dan `components.yaml`. Menggunakan server-side apply menghapuskan kendala API server payload timeout.
2. **Eliminasi 503 Aggregation Loop K3s**:
   - Menambahkan `--disable=metrics-server` pada `cluster-config.yaml` guna mencegah SQLite (Kine) transaction lock selama 21 detik di WSL2.
3. **Penyelesaian Timeout Named Pipe WSL2**:
   - Menaikkan timeout pembuatan klaster K3d dari `180s` menjadi `360s` agar tahan terhadap latensi I/O disk WSL2 Windows.
4. **Isolasi Environment PATH Windows**:
   - Pembuatan wrapper script [`scripts/exec.ps1`](file:///d:/agent%20v2/scripts/exec.ps1) dan auto-refresh PATH di semua script `.ps1` memastikan CLI (`docker`, `k3d`, `kubectl`, `go`) dapat dieksekusi tanpa ketergantungan sesi manual.
5. **Pencegahan OOM RAM WSL2**:
   - Mengganti sample app monolitik besar (`sock-shop`) dengan lightweight deployment terukur (`sample-nginx`, `sample-httpbin`, `helm-guestbook`) sehingga total konsumsi RAM klaster tetap di bawah 950 MB.
