# Dokumentasi Komprehensif Penyelesaian Fase 10: Halaman Settings & Administrasi

## 1. Ringkasan Eksekutif (Executive Summary)
Fase 10 (**Halaman Settings & Administrasi**) dari platform **CIFO Monitoring Platform (Enterprise AIOps)** telah diselesaikan secara tuntas dan menyeluruh sesuai dengan spesifikasi pada `arsitektur_diskusi/arsitektur_sistem.md` (Bagian 2 & 4), `arsitektur_diskusi/plan.md` (baris 1128-1156), dan `arsitektur_diskusi/agent_instructions.md`.

Fase ini mengimplementasikan tata kelola konfigurasi platform menyeluruh, mencakup preferensi global, integrasi notifikasi Alertmanager & Telegram, parameter operasional AI Engine (ambang batas keyakinan & auto-remediasi), administrasi pengguna berbasis Role-Based Access Control (RBAC), tata kelola sesi & keamanan (MFA/inactivity timeout), serta pencatatan jejak audit (*immutable audit trail*) ke dalam PostgreSQL secara real-time.

Platform mematuhi secara ketat prinsip **Zero Mock Data**, menghubungkan langsung ke PostgreSQL `cifo_db`, Redis cache & rate limiter, Keycloak OIDC, Docker daemon live, K3d Kubernetes cluster, dan microservice AI Python FastAPI live.

## 3. Rincian Implementasi per Layer

### 3.1. Database Layer (PostgreSQL Migrations)
1. **Migration 008 (`apps/backend/migrations/008_create_system_settings.up.sql`)**:
   - Menambahkan migrasi cerdas yang memeriksa keberadaan tabel legacy key-value dan merename menjadi `system_settings_kv` secara transparan tanpa kehilangan riwayat data awal.
   - Membuat tabel baru `system_settings` dengan struktur kolom konfigurasi lengkap:
     - `app_name` VARCHAR(100) NOT NULL DEFAULT 'CIFO Platform'
     - `default_theme` VARCHAR(20) NOT NULL DEFAULT 'dark'
     - `language` VARCHAR(10) NOT NULL DEFAULT 'id'
     - `timezone` VARCHAR(50) NOT NULL DEFAULT 'Asia/Jakarta'
     - `ai_default_model` VARCHAR(50) NOT NULL DEFAULT 'gemini-2.0-flash'
     - `ai_default_provider` VARCHAR(50) NOT NULL DEFAULT 'google'
     - `ai_monthly_budget_usd` NUMERIC(10,2) NOT NULL DEFAULT 50.00
     - `ai_max_tokens_per_request` INTEGER NOT NULL DEFAULT 4096
     - `ai_model_preference_order` TEXT[] NOT NULL DEFAULT ARRAY['google', 'openai', 'anthropic', 'ollama', 'mock']
     - `session_timeout_minutes` INTEGER NOT NULL DEFAULT 60
     - `max_login_attempts` INTEGER NOT NULL DEFAULT 5
     - `require_mfa` BOOLEAN NOT NULL DEFAULT false
     - `maintenance_mode` BOOLEAN NOT NULL DEFAULT false
     - `created_at` & `updated_at` TIMESTAMPTZ NOT NULL DEFAULT NOW()
   - Melakukan seeding otomatis jika record awal belum tersedia menggunakan klausa `WHERE NOT EXISTS`.
   - Melakukan seeding awal pada tabel `notification_settings` (`vault:secret/telegram#token`, `-100123456789`, `inapp_enabled: true`).

2. **Down Migration (`apps/backend/migrations/008_create_system_settings.down.sql`)**:
   - Skrip rollback aman untuk menghapus tabel `system_settings` jika diperlukan.

### 3.2. Backend Go Layer (`apps/backend`)
1. **Model Domain (`internal/model/settings.go`)**:
   - `SystemSettings`, `NotificationSettings`, `CombinedSettings`.
   - `UpdateSettingsRequest` dengan dukungan model ganda (flat fields dan nested partials `System` & `Notification`) untuk kompatibilitas mutlak.
   - `UpdateUserRoleRequest` dan `UpdateUserStatusRequest`.
2. **Repository Layer**:
   - `internal/repository/user_repository.go`: Ditambahkan method `UpdateRole(ctx, id, role)` dan `SetActive(ctx, id, isActive)` ke interface `UserRepository` dan `PostgresUserRepository`.
   - `internal/repository/settings_repository.go`: Interface `SettingsRepository` dan implementasi `PostgresSettingsRepository` dengan pgxpool query untuk `GetSystemSettings`, `UpdateSystemSettings`, `GetNotificationSettings`, dan `UpdateNotificationSettings`.
3. **Service Layer (`internal/service/settings_service.go`)**:
   - `DefaultSettingsService`:
     - Penggabungan konfigurasi dinamis.
     - Validasi RBAC role (`admin`, `devops`, `viewer`).
     - Proteksi mandiri akun (*Self-protection*): Mencegah akun admin menonaktifkan dirinya sendiri (`cannot deactivate your own account`).
     - Pengiriman test alert via Telegram service dengan payload insiden uji coba.
     - Pencatatan otomatis ke `auditRepo.Create()` untuk aksi `SETTINGS_UPDATE`, `USER_ROLE_CHANGE`, `USER_DEACTIVATION`, `USER_ACTIVATION`, dan `TELEGRAM_TEST_ALERT`.
   - `internal/service/settings_service_test.go`: Unit test lengkap mencakup seluruh skenario (100% lulus).
4. **Handler Layer (`internal/handler/settings_handler.go`)**:
   - Endpoint Echo terstruktur dengan standard envelope `{ "data": ... }`.
   - Penanganan error RFC 7807 `ProblemDetail`.
   - Ekstraksi IP address dan actor ID dari context token JWT.
   - `internal/handler/settings_handler_test.go`: Unit test handler dengan mock service (100% lulus).
5. **Wiring & Routing (`cmd/server/main.go`)**:
   - Inisialisasi `SettingsRepository`, `SettingsService`, dan `SettingsHandler`.
   - Pendaftaran group route `/api/v1/settings` yang dilindungi ganda:
     - `middleware.RequireAuth(authService)` (verifikasi token JWT / OIDC Keycloak).
     - `middleware.RequireRole(authService, "admin")` (enforce role admin; viewer dan devops ditolak dengan HTTP 403 Forbidden).
   - Alias RESTful routes:
     - `GET /api/v1/settings`
     - `PUT /api/v1/settings`
     - `POST /api/v1/settings/test-notification` & `POST /api/v1/settings/notifications/test`
     - `GET /api/v1/settings/users`
     - `PUT /api/v1/settings/users/:id/role`
     - `POST /api/v1/settings/users/:id/deactivate` & `DELETE /api/v1/settings/users/:id`
     - `POST /api/v1/settings/users/:id/reactivate` & `PUT /api/v1/settings/users/:id/activate`

### 3.3. Frontend Next.js 16 Layer (`apps/frontend`)
1. **Types (`src/types/settings.ts`)**:
   - Definisi TypeScript untuk `SystemSettings`, `NotificationSettings`, `CombinedSettings`, `UpdateSettingsRequest`, `UserAdmin`, dan `ActiveSession`.
2. **Service Client (`src/services/settings-service.ts`)**:
   - Implementasi API client berbasis Axios yang terintegrasi dengan auth interceptor (`apiClient`).
   - Mendukung method `getSettings`, `updateSettings`, `testNotification`, `listUsers`, `updateUserRole`, `deactivateUser`, dan `reactivateUser`.
   - Unit tests di `src/services/settings-service.test.ts` (7/7 tes lulus).
3. **Interactive UI (`src/app/(dashboard)/settings/page.tsx`)**:
   - Tampilan Cyberpunk Glassmorphic responsif dengan 5 tab interaktif:
     1. **General Tab**: Konfigurasi nama platform, periode retensi telemetri (7/14/30/90 hari), refresh interval real-time (5s/10s/30s/60s), dan timestamp pembaruan terakhir.
     2. **Notifications Tab**: Konfigurasi Telegram Bot (toggle switch, masked bot token dengan show/hide eye toggle, Chat ID, tombol dispatch uji coba instan "Test Notification Alert"), Email Dispatch Gateway, Severity Routing matrix (Critical, Warning, Info, Auto-resolve), dan Quiet Hours scheduler (Start/End time picker).
     3. **AI Configuration Tab**: Indikator status live microservice AI Python (Connected on `http://127.0.0.1:8000`), slider ambang batas keyakinan analisis (Confidence Threshold slider 50% - 99%), dan toggle Autonomous Remediation Mode dengan warning banner tingkat tinggi.
     4. **Users & RBAC Tab**: Direktori pengguna platform live (4 akun terdaftar dari database PostgreSQL), selector dropdown peran dinamis (`admin`, `devops`, `viewer`), badge status aktif/non-aktif, tombol Deactivate/Reactivate dengan perlindungan diri (`Self Protected`). Menampilkan warning banner jika diakses oleh non-admin.
     5. **Security & Sessions Tab**: Kebijakan sesi dan keamanan (Inactivity Timeout 15/30/60/120 menit, toggle enforced Keycloak MFA/WebAuthn), serta visualisasi daftar sesi aktif perangkat pengguna dengan opsi "Revoke Other Sessions".
   - Toast notification dinamis (hijau untuk sukses, merah untuk kegagalan) dengan animasi slide-in.
   - Unit tests di `src/app/(dashboard)/settings/page.test.tsx` (5/5 tes lulus).
