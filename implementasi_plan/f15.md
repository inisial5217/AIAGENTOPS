   - Protokol real-time WebSocket (`/ws`), multiplexing channel subscription, frame heartbeat ping/pong setiap 30 detik, dan penanganan auto-reconnect.

5. **Tugas 15.5: Security Policy & Compliance Manual (`docs/security-policy.md`)**:

   - Rotasi kredensial dinamis Vault Database Engine dan Transit Secrets wrapping.
   - Kebijakan Zero-Trust Kubernetes NetworkPolicies (default-deny).
   - Jejak audit append-only (`audit_log` dan `ai_action_audit_log`) serta protokol penanganan data breach.

## 3. Rangkuman Spesifikasi Teknis per Tugas

### 3.1 Tugas 15.1: Dokumentasi API & Protokol WebSocket (`docs/api-reference.md`)
- **Autentikasi**: Mendokumentasikan otentikasi Bearer JWT OIDC dan 3 token developer bawaan (`dev-token-admin`, `dev-token-devops`, `dev-token-viewer`).
- **Rate Limiting**: Header standar `X-RateLimit-Limit`, `X-RateLimit-Remaining`, dan `X-RateLimit-Reset` berbasis sliding window Redis (100 req/s global, 20 req/menit untuk chat AI).
- **Format Kesalahan**: Struktur error JSON seragam dengan field `code`, `message`, `details`, dan `timestamp`.
- **WebSocket Protocol**: Menjelaskan siklus hidup koneksi WebSocket di `/ws`, format frame handshake, pesan JSON channel multiplexing (`subscribe`, `unsubscribe`), dan frame ping/pong periodik 30 detik.

### 3.2 Tugas 15.2: Dokumentasi AI Agent (`docs/ai-agent-capabilities.md`)
- **Tool Calling Inventory**: 8 Read-Only tools (`get_pod_status`, `get_container_logs`, `get_argocd_app_status`, `get_deployment_info`, `get_node_resources`, `get_docker_stats`, `list_docker_containers`, `get_argocd_history`) dan 5 Write tools (`restart_deployment`, `scale_deployment`, `sync_argocd_app`, `restart_container`, `stop_container`).
- **Human-in-the-Loop Approval**: Prosedur konfirmasi aksi tulis oleh engineer berwenang melalui UI modal.
- **Circuit Breaker**: Mekanisme failover otomatis (3 kegagalan dalam 60s memicu peralihan model, 120s cooldown half-open).
- **Hardcoded Blocklist**: Pencegahan mutlak eksekusi perintah destruktif (`delete namespace`, `delete node`, `system prune`, `--force`).

### 3.3 Tugas 15.3: Deployment Guide & Disaster Recovery Runbooks
- **Deployment Produksi**: Instruksi langkah demi langkah instalasi menggunakan Helm Chart `cifo-platform` dan Kustomize overlays staging/production.
- **SLO Pemulihan Bencana**: Target RTO $\le 60\text{ menit}$ dan RPO $\le 5\text{ menit}$.
- **PostgreSQL PITR**: Prosedur pemulihan point-in-time via pgBackRest dan integrasi WAL archiving.
- **Vault Unseal & Restore**: Prosedur penanganan unseal menggunakan Shamir key shares dan snapshot restore Raft storage.

### 3.4 Tugas 15.4: Incident Response Runbook & SOPs
- **Severity Levels**: Klasifikasi insiden CRITICAL (P1: respon $< 5\text{m}$, resolusi $< 30\text{m}$), WARNING (P2: respon $< 15\text{m}$), dan INFO (P3).
- **Eskalasi 15-Menit**: Alert yang tidak di-acknowledge dalam 15 menit otomatis di-escalate ke level Lead SRE melalui Telegram alert bertag `[ESCALATED]`.
- **Mitigasi Alert Storm**: Penggabungan dan deduplikasi alert beruntun ($> 10$ alert/menit) menjadi satu pesan ringkasan untuk mencegah throttling Telegram API.
- **SOP Kegagalan Kritis**: Panduan mitigasi konkret untuk CrashLoopBackOff, OOMKilled, sinkronisasi ArgoCD gagal, kebocoran koneksi database, dan degradasi layanan AI.

### 3.5 Tugas 15.5: Security Policy & Compliance Manual
- **Matriks RBAC**: Pemetaan granular hak akses untuk peran Admin, DevOps, dan Viewer.
- **Standar Autentikasi**: JWT Access Token (TTL 15 menit), HttpOnly Refresh Token (TTL 7 hari), dan MFA berbasis TOTP / WebAuthn.
- **Zero-Trust Network Policies**: Pembatasan komunikasi ingress dan egress antar pod berbasis CNI NetworkPolicy.
- **Audit Trail Immutabilitas**: Hak database pengguna aplikasi dibatasi hanya `INSERT` dan `SELECT` pada tabel `audit_log` dan `ai_action_audit_log`, serta prompt hashing menggunakan SHA-256.

### 3.6 Tugas 15.6: Architecture Decision Records (ADR 001 - 005)
- **ADR 001**: Pemilihan router berbasis standard library `net/http` (Echo / Chi) dan menolak Fiber (`fasthttp`) demi kompatibilitas middleware OpenTelemetry, OIDC, dan Prometheus.
- **ADR 002**: Pemilihan VictoriaMetrics untuk penyimpanan metrik time-series jangka panjang dengan penghematan storage 10x dan kompatibilitas PromQL penuh.
- **ADR 003**: Pemisahan layanan AI ke microservice independen Python 3.12 (FastAPI + LangChain) via gRPC internal demi kestabilan ekosistem AI terkini.
- **ADR 004**: Penerapan Pola Multi-Model Fallback dan Circuit Breaker untuk ketersediaan tinggi 99.9% dan fleksibilitas biaya token.
- **ADR 005**: Kebijakan absolut Zero Mock Data di seluruh repositori untuk memastikan sistem selalu terintegrasi dengan testbed nyata (Docker, K8s, ArgoCD).
